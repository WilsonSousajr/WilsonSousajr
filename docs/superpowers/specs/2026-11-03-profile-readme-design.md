# GitHub profile README — design

Date: 2026-11-03 · Repo: `WilsonSousajr/WilsonSousajr` (public, branch `main`)

## Intent

Recruiters and developers land on github.com/WilsonSousajr. In a few seconds they
should get who Wilson is, then click through to **wstech.tech** and the **blog**
(blog.wstech.tech). The README is a doorway, not a CV. It should look like a small
cousin of wstech.tech: a monochrome bento grid of "boxes".

The current README is stale ("Senior FullStack Developer", green shields.io
badges, Twitter, an old LinkedIn URL with an accent) and gets fully replaced.

## Goals

- Show the positioning at a glance: **Full Stack Engineer · distributed systems and
  high-performance APIs · Python**.
- Get people to click through to the website and blog. The README itself stays
  thin.
- Visually echo wstech.tech: a bento grid of rounded, flat smoky cards, Outfit
  type, neutral grays.
- Look right in both GitHub dark and light themes.

## Non-goals / anti-goals

- No third-party stats services (github-readme-stats and similar): they
  rate-limit and break, they clash visually, and they're noise to recruiters.
- No contribution heatmap card. GitHub already shows its graph right below the
  README.
- No typing banners, spinning icons, badge walls or trophies.
- No dune photo or glass refraction. That look was only wanted with parallax,
  which GitHub can't do: images get no scroll or pointer events and no JS.
- Failure even if it "works": a broken image on the profile, mismatched
  dark/light versions, or text that can't be read at GitHub's README width.

## Layout (decided): full bento, flat smoky

GitHub's README column is ~830px wide on desktop and shrinks on mobile. Each box
is its own SVG image wrapped in its own link, since GitHub has no clickable
regions inside one image. Order, top to bottom:

1. **Profile card**, full width. A "Full Stack Engineer" pill, **Wilson Sousa**,
   the line "Distributed systems & high-performance APIs · Brasília", and chips:
   Python, FastAPI, Django, PostgreSQL, Go, TypeScript. Links to
   https://wstech.tech.
2. **Three link cards in one row**, each with a small ↗ arrow like the site's
   external NavCard. Label / title / sub:
   - WEBSITE / wstech.tech / Projects & about → https://wstech.tech
   - BLOG / Read articles / Engineering notes → https://blog.wstech.tech
   - LINKEDIN / Connect / Experience & CV → https://www.linkedin.com/in/wilsonsousajr
3. **Stat card**, full width. Label "GitHub activity · last 12 months", then
   three figures side by side: **contributions**, **longest streak (days)** and
   **repositories contributed to**, all over the last 12 months. Links to
   https://github.com/WilsonSousajr.
4. **A plain markdown line** under the grid: email
   `wstechnology.br@gmail.com` (mailto). It doubles as the readable fallback.

Visual style: flat smoky. Dark is a near-black gray gradient card (~#262626 →
#141414) with a 1px hairline rim and a faint top inner highlight. Light follows
the site's light theme: pale gray card, darker text. Radii and type scale match
wstech.tech: label 9–10px uppercase tracked, titles semibold, Outfit. The exact
tokens are in `wstech` `src/index.css` and the home components.

## Dark / light

Every card ships as `<name>-dark.svg` and `<name>-light.svg`, switched with
`<picture><source media="(prefers-color-scheme: dark)" …><img …></picture>`.
Don't rely on `prefers-color-scheme` inside the SVG: GitHub doesn't honor it for
the page theme.

## Animations (decided: subtle)

- **Entrance:** cards fade up in sequence on load (staggered, ~600ms each), like
  the wstech.tech home. Each SVG is a separate image, so the stagger comes from a
  per-card animation delay baked in at generation time.
- **Light sweep:** a slow highlight travels along each card's rim, echoing the
  site's moving light source. It loops slowly and stays low-contrast.
- Pure CSS inside each SVG (no JS, no SMIL requirement), wrapped in
  `@media (prefers-reduced-motion: reduce)` → static.
- The final resting frame must look complete, so a frozen or blocked animation
  still shows a finished card.

## Text and accessibility

- Card text is converted to vector outlines. SVG-as-image can't load web fonts,
  and system fallbacks would break the look. Generate outlines from the Outfit
  font at build time.
- Every `<img>` gets alt text containing the card's real content, e.g. the
  profile card's alt holds the name, title, tagline and stack.

## How it gets made (decided)

- A small **Node script in the profile repo** generates all SVGs from one data
  file (text, links, colors per theme), so dark and light can't drift apart.
- A **GitHub Action** runs daily, plus manual dispatch and on push to the
  generator. It fetches the stats, regenerates the stat card SVGs and commits
  only if they changed.
- Static cards (profile, links) are generated by the same script and committed.
  They only change when the data file changes.

## Stat data (decided)

- **Window: rolling last 12 months**, not the calendar year. It matches what
  wstech.tech fetches (jogruber `?y=last`) and never shows a near-empty card in
  January.
- Source: the GitHub GraphQL API `contributionsCollection(from: now-1y, to: now)`.
  Total and longest streak come from `contributionCalendar`, and the third figure
  from `totalRepositoriesWithContributedCommits`.
- **No "most used language".** By bytes it's Go (one large repo, `omatty`),
  which would contradict the Python-first profile card. Replaced by repositories
  contributed to (Claude's call, approved by Wilson as "go with your
  recommendation").
- If the fetch fails, keep the last committed stat SVGs. Never commit an
  empty or broken card.
- Token: start with the Action's `GITHUB_TOKEN`. If private contributions are
  missing from the totals compared with wstech.tech, a fine-grained PAT secret is
  the follow-up (flag it, don't silently ship mismatched numbers).

## Related fix on wstech.tech (decided)

The site's GitHub card (`wstech` `src/components/home/GitHubHeatmap.tsx`) shows
the last 12 months but labels it with the current year ("GitHub activity • 2026",
"N activities in 2026"). Relabel it to "last 12 months" in EN and PT-BR i18n so
the site and the README agree. This is a separate commit in the `wstech` repo.

## Constraints

- GitHub sanitizes README HTML: no CSS or scripts in the markdown. Use only
  `<picture>`, `<source>`, `<img>`, `<a>`, `<p align>` and similar allowed tags.
- Images are served through GitHub's camo proxy and must be committed in the
  repo, referenced by relative path.
- Keep each SVG small (aim under ~50KB). Outlined text adds weight, so subset to
  the glyphs used.
- Layout must hold at mobile width. On narrow screens the three link cards may
  wrap, which is fine as long as they stay readable.
- All links to external sites are plain `<a href>`. GitHub adds its own `rel`.

## Delivery

- **Pushing to `main` updates the public profile immediately**, so it needs
